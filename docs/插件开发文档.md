# VaIMod 插件开发文档

插件 = 一个 `.js` 文件，内部调用 `VaIMod.plugin({ ... })` 声明自己。装好后成为面板里的一个独立标签页。

---

## 1. 安装与分发

- **安装**：面板头部设置图标 → 插件 → 上传插件 JS（支持多选）。
- **导入配置包自动安装**：导出的配置文件自带全部插件源码，换设备导入即自动装回。
- **去重与升级**：源码指纹一致 → 跳过；同 `id` 不同源码 → 覆盖升级（保留启用态）。
- **停用 / 卸载**：停用后 Tab 消失但源码保留；卸载会连设置和私有存储一起清除。

## 2. 最小示例

```js
VaIMod.plugin({
  id: 'hello',
  name: '你好',
  html: '<button class="btn">点我</button>',
  css: '.btn { padding: 6px 14px; border-radius: 8px; }',
  code(ctx) {
    let n = ctx.store.get('n', 0);
    ctx.root.querySelector('.btn').onclick = () => {
      n++;
      ctx.store.set('n', n);
      ctx.toast(`点了 ${n} 次`);
    };
  },
});
```

保存为 `hello.plugin.js` → 上传即可。完整模板见 [plugin-template.example.js](./plugin-template.example.js)，可直接上传试装。

## 3. 插件类型（必须在定义开头声明）

```js
VaIMod.plugin({
  type: 'ext',   // 'ext' = 扩展（带标签页）| 'patch' = 安全补丁（无界面）
  ...
});
```

| | **扩展 `ext`** | **补丁 `patch`** |
|---|---|---|
| 定位 | 功能扩展：带标签页 UI | 安全补丁：沙盒加固、遮罩联动、安全模块拦截器等 |
| 界面 | 标签栏有以 `name` 命名的 Tab | **无标签页**，headless 后台运行 |
| code 执行时机 | 用户切到对应 Tab 时 | 面板挂载后立即执行一次 |
| 专属能力 | `ctx.root` / `html` / `css` | `ctx.patch.hooks`（参与内部管道） |
| `priority` | 无意义 | 管道优先级，越小越先过链（0–10000，默认 100） |
| 安装 | 直接安装 | 弹确认框（补丁参与内部管道，需确认来源可信） |

未声明 `type` 的旧格式插件按 `'ext'` 兼容；声明了其它值会在解析时报错。

**补丁管道**（当前可用：`variable:write` 变量写回链）：

```js
code(ctx) {
  ctx.patch.hooks.add('variable:write', (value, meta) => {
    // meta = { id, name, targetId, isCloud, kind }
    if (meta.isCloud) return false;   // 拒绝所有云变量写回
    return value;                     // 或改写值；return undefined = 放行不改
  });
}
```

- 每个补丁在每个管道上只能注册一个钩子（重复注册覆盖旧的）；
- 全局钩子总数上限 32；
- 钩子抛错自动熔断（连续 3 次错误禁用该钩子），不会拖垮写回链路；
- 钩子随补丁生命周期自动注销（卸载 / 禁用 / 升级时）。

完整补丁示例见 [plugin-patch.example.js](./plugin-patch.example.js)（云变量写保护，可直接上传试装）。

## 4. `VaIMod.plugin(def)` 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | ✓ | 插件类型，**必须在开头声明**：`'patch'`（安全补丁）或 `'ext'`（扩展）；缺省按 `'ext'` 兼容旧插件 |
| `id` | ✓ | 唯一标识，2–48 位小写字母/数字/`-`/`_`。**改 id 等于新插件**（旧数据不清但卡片消失） |
| `name` | ✓ | 标签页标题（补丁显示为卡片名） |
| `priority` | | 补丁管道优先级（仅 `type:'patch'` 有意义），越小越先过链，默认 100 |
| `version` | | 默认 `'1.0.0'`，展示在插件卡片 |
| `author` / `desc` | | 展示在插件卡片 |
| `css` | | 内容区样式（仅扩展）。每条选择器自动加 `#vmp-<id>` 前缀，只影响本插件，不外泄；`&` 开头展开为容器自身（如 `&.active{...}` → `#vmp-<id>.active{...}`）；`@media` / `@keyframes` 原样保留 |
| `html` | | 内容区 HTML 字符串（仅扩展），先注入后跑 `code`；不写则由 code 自行构造 |
| `code` | | 功能代码。**建议函数形态** `code(ctx) { ... }`（自动规整）；字符串形态 = 函数体语句，`ctx` 是入参。可 `return` 一个清理函数 |
| `refresh` | | **刷新钩子**：用户点击面板「刷新」按钮且停在本插件标签页时执行。函数形态 `refresh(ctx) { ... }`，拿到与 `code` 同一个 `ctx`（`ctx.variables()` 读取实时）。只做数据重取/重渲染，**不要在这里重新订阅** `onVariables` / `onSettings`（会造成重复订阅）。⚠️ 它与 `code` **不共享闭包**，共享状态只能经 `ctx.root.__xxx` 传递，见 §12 第 12 条。未定义时点击「刷新」只重播进入动画 |
| `settingsCss` | | 设置页样式。**注入整个设置覆盖层、不自动加前缀**，选择器要写具体，别用裸标签名 |
| `settings` | | 设置页功能项定义，见下节（补丁也可以有设置项） |
| `async` | | **异步加载定义**（扩展/补丁都可写），见 §4.1。缺省 = 保守同步，时序与旧版完全一致 |
| `market` | | **市场元信息**（分类/标签/图标/主页/许可证…），见 §4.2。只作展示与检索，不影响运行 |
| `extra` | | 任意 JSON 可序列化数据，`ctx.extra` 原样透传 |

### 4.1 `async` 异步加载定义

插件清单里填写，控制「什么时候、等什么、等多久」再执行 `code`。四个字段全部可选。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `code` | boolean | `false` | 声明 `code` 是异步的（返回 Promise）。清理函数会在 Promise 落定后才接管 |
| `waitVm` | boolean | `false` | 等 vm 就绪后再执行 `code`。等待期间标签页显示「插件加载中…」而不是空面板 |
| `load` | string / function | `''` | **预加载钩子**：在 `code` 之前执行，可 async。用于按需拉远程资源 / 初始化大依赖 |
| `timeout` | number | `0` | 上面两项的等待上限（ms）。`0` = 不限制（面板侧另有 120s 兜底，避免永不终止的等待挂住定时器） |
| `lazy` | boolean | 扩展 `true` / 补丁 `false` | 懒加载。`true` = 打开标签页才执行 `code`；`false` = **常驻**，不打开标签页也跑 |

```js
async: {
  waitVm: true,          // 等 vm 就绪
  timeout: 8000,         // 最多等 8s
  code: false,           // code 本身不是 async 函数
  lazy: true,            // 打开本插件标签页才跑（默认）
  // load: `await fetch('/api/warmup');`,   // 预加载钩子（可 async）
}
// 简写：async: true  等价于 async.code === true
```

**失败语义（重要）**：`waitVm` 等不到 vm、或 `load` 抛错，都按**加载失败**处理——**不执行 `code`**，标签页内显示失败原因。这样「我本该在有 vm 时才工作」的插件不会带着空数据跑起来产生副作用。

**常驻扩展（`lazy: false`）**：不打开标签页也会执行 `code`。此时实例是 **headless** 的——
不注入 `html`、不渲染任何面板 DOM，`ctx.root` 是一个**游离节点**（可读写，但不进文档树、
不显示）。所以常驻插件只应做后台工作（写变量、订阅、`ctx.toast`），不要依赖 `root` 里的
元素可见或可测量。当前正被打开的那个插件标签页不会重复实例化（避免双跑）。

```js
market: {
  category: '工具',                 // 上架分类
  tags: ['变量', '批量'],           // 检索关键词
  icon: '🧰',                       // emoji 或图片 URL
  homepage: 'https://…',            // 主页 / 仓库
  license: 'MIT',                   // 许可证
  minApp: '1.0.0',                  // 最低本体版本
  changelog: '修复…',               // 版本更新说明
  screenshots: ['https://…'],       // 截图 / 示例链接
}
```

### 4.3 `@标签式清单`

除对象写法外，还可以把清单写在**文件开头的注释区**（扫到第一行真实代码即停止）：

```js
//  @id my-tool
//  @name 我的工具
//  @type ext
//  @version 1.0.0
//  @desc 一行说明
//  @priority 100
//  @async true
//  @waitVm
//  @lazy false
//  @timeout 8000
//  @market.category 工具
//  @market.tags 变量,批量
//  @settings [{"type":"toggle","key":"on","label":"开关","def":true}]
//  @css
//    .wrap { display: flex; }
//  @html
//    <div class="wrap">…</div>
VaIMod.plugin({ /* 可以只写 code，其余走标签 */ });
```

- 单行值 `@key value` / `@key: value`；布尔开关裸写即 `true`（`@async false` 为 `false`）。
- **块值**：`@html` / `@css` / `@code` / `@refresh` / `@load` 之后每一行都属于它，
  直到下一个 `@标签` 为止（可多行）——这正是把长内容放进注释区的好处。
- 点号命名空间：`@market.category` → `market.category`。
- `@settings` 的值是一段 JSON（`settings` 是数组，没法写成块值）。
- **两种写法可混用，对象优先**：**所有字段**都支持标签回退（`id`/`name`/`type`/`version`/
  `author`/`desc`/`priority`/`css`/`html`/`code`/`refresh`/`settingsCss`/`settings`/`async`/
  `load`/`market`）。对象里写了就用对象，没写才看标签。
- 未识别的标签原样收进 `extra.tags`，`@market.*` 一律收进 `extra.marketTags`
  （已知的市场键在 `def.market` 里另有一份规整后的值），可以自行扩展新标签而不必改本体。

## 5. `settings` 设置项

四种类型，同一插件内 `key` 必须唯一；缺 `key`/`label`、select 无 options、key 重复的项会被静默丢弃。

```js
settings: [
  // 开关（def 默认 true）
  { type: 'toggle', key: 'on',   label: '开关', desc: '说明文字', def: true },
  // 文本（def 默认 ''）
  { type: 'text',   key: 'name', label: '名称', placeholder: '提示', def: '' },
  // 数字（def 默认 0）
  { type: 'number', key: 'min',  label: '下限', def: 0 },
  // 下拉（def 默认第一个 option）
  { type: 'select', key: 'mode', label: '模式',
    options: [ { value: 'a', label: '方案A' }, { value: 'b', label: '方案B' } ] },
]
```

设置值在设置页改动后**整页重建并重跑 code**，`ctx.settings` 拿到的就是最新值。

## 6. `ctx` 能力面

| 成员 | 说明 |
|---|---|
| `root` | 本插件内容容器（`HTMLElement`，`html` 已注入；在 closed shadow 内）。**补丁的 root 是游离节点**，不要操作它 |
| `store.get(key, def)` / `set(key, value)` / `remove(key)` | 私有存储：localStorage 命名空间隔离（key 自动加 `vaimod_plug_<id>_` 前缀），值 JSON 序列化 |
| `settings` | 当前设置值对象（缺项用 `def` 兜底） |
| `onSettings(cb)` | 设置变化回调，返回取消订阅函数 |
| `variables()` | 变量快照（只读数组）：`{ id, name, kind: 'variable'\|'list', value, isCloud, targetId, targetName, isLocked }`，含云变量与安全变量 |
| `onVariables(cb)` | 变量变化通知（约 1.2s 轮询 + 事件合并），返回取消订阅函数；cb 里再调 `variables()` 取新值。**补丁的订阅随补丁生命周期自动退订** |
| `write(variableId, value, targetId?)` | 写变量（走面板统一写回管道：多层安全栈 + 补丁拦截 + 锁变量同步）。安全变量无需 `targetId`；列表传数组或逗号串。结果经面板 toast 反馈 |
| `ui` | **UI 样式接口**：与主面板同质感的组件工厂，见下一节 |
| `toast(text, kind?)` | 面板提示，`kind` 为 `'ok'`（默认）或 `'err'` |
| `project` | **作品能力面**：sb3/sprite3 导出、角色打包、loadProject 捕获，见第 8 节 |
| `patch` | **仅补丁存在**：`patch.hooks.add(point, fn)` 注册管道钩子 / `patch.hooksRemoveAll()` 注销本补丁全部钩子 |
| `id` / `extra` | 插件标识 / `def.extra` 原样透传 |

## 7. `ctx.ui` 样式接口

主面板开放给插件的内置组件工厂：不想手写 `css` 时，用 `ctx.ui.*` 拼出来的界面**自动与面板同质感**（主色跟随设置里的主题色，深浅毛玻璃、圆角、动效全部内置）。组件类名统一 `.vpu-*`。

```js
code(ctx) {
  const ui = ctx.ui;
  const name = ui.input({ placeholder: '变量名', onenter: (v) => search(v) });
  const mode = ui.tabs({
    value: 'all',
    options: [{ value: 'all', label: '全部' }, { value: 'cloud', label: '云变量' }],
    onchange: (v) => filter(v),
  });
  const bar = ui.progress({ value: 30, tone: 'primary' });
  bar.update(70);                       // 更新进度
  const apply = ui.button({
    text: '应用',
    style: 'flex:1',                    // 所有组件都支持内联 style
    onclick: () => doApply(),
  });
  ctx.root.append(
    ui.card({ title: '查找变量', children: [mode, ui.row(name, apply), bar] }),
    ui.tip('提示：支持模糊匹配', 'info'),
  );
}
```

### 7.1 接口总表

| 分类 | 接口 | 说明 |
|---|---|---|
| 提示类 | `ui.toast(text, kind?)` | 面板级 toast，`kind`: `'ok'` / `'err'` / `'info'` |
| 提示类 | `ui.tip(text, kind?, custom?)` | 内联提示条（放进内容流），`kind`: `'info'` / `'ok'` / `'warn'` / `'err'` |
| 提示类 | `ui.badge(text, tone?, custom?)` | 徽标胶囊，`tone`: `'default'` / `'primary'` / `'ok'` / `'warn'` / `'err'` |
| 按钮类 | `ui.button({ text, kind, onclick, ... })` | `kind`: `'primary'`（默认主色）/ `'ghost'`（次级）/ `'danger'`（红色危险） |
| 开关类 | `ui.switch({ checked, label, onchange, ... })` | 滑块开关，`onchange(on)` 回调布尔值 |
| 框选类 | `ui.check({ text, checked, onchange, ... })` | 复选框（勾选样式随主色） |
| 框选类 | `ui.radioGroup({ value, options, onchange, ... })` | 分段单选组（等宽 grid 胶囊，`options: [{value,label}]`） |
| 框选类 | `ui.tabs({ value, options, onchange, ... })` | 标签页切换（下划线式，与 radioGroup 视觉区分） |
| 框选类 | `ui.select({ value, options, onchange, ... })` | 下拉选择 |
| 输入类 | `ui.input({ value, placeholder, type, oninput, onenter, ... })` | 单行输入框，`type`: `'text'` / `'number'` / `'password'`；`onenter` 回车触发 |
| 输入类 | `ui.textarea({ value, placeholder, rows, oninput, ... })` | 多行输入框（可纵向拉伸） |
| 反馈类 | `ui.progress({ value, max, tone, ... })` | 进度条，`tone`: `'primary'` / `'ok'` / `'warn'` / `'err'`；返回元素带 **`update(value, max?)`** 方法 |
| 反馈类 | `ui.spinner(custom?)` | 加载态旋转圈 |
| 反馈类 | `ui.divider(custom?)` | 水平分隔线 |
| 布局类 | `ui.card({ title, children, ... })` / `ui.row(...nodes)` | 卡片容器（可选标题）/ 水平行 |
| 布局类 | `ui.field({ label, children, ... })` | 带标签的表单字段（label 在上、控件在下） |
| 弹窗类 | `ui.confirm({ title, message, okText, danger, ... })` | **面板内异步确认框**，返回 `Promise<boolean>`（Esc/点遮罩=取消，Enter=确认）。不依赖 `window.confirm`——部分站点会吞掉原生弹窗 |
| 弹窗类 | `ui.modal({ title, message, children, actions, maskClosable, ... })` | **自定义内容弹窗**，返回 `{ el, box, close() }`；Esc / 点遮罩关闭（`maskClosable: false` 关掉遮罩关闭）。**仅扩展插件可用**（补丁无挂载点会抛错） |
| 补丁差异 | （补丁 ctx 同样有 `ui`） | 补丁 headless 无面板挂载点：`toast` 可用，`confirm` 自动退回浏览器原生弹窗，`modal` 抛错，其余工厂照常可用 |

### 7.2 自定义样式（三条通道）

**① `class` / `style` 选项（所有组件都支持）**

每个工厂的 opts 都接受可选的 `class`（追加类名）与 `style`（内联 style 字符串）：

```js
ui.button({ text: '发奖', onclick: grant, style: 'width:100%; letter-spacing:2px' });
ui.card({ title: '状态', children: [cards], class: 'my-fancy-card', style: 'gap:14px' });
```

`style` 是**弹窗类组件唯一的自定义样式通道**：`confirm` / `modal` 挂在面板 ShadowRoot 直下、在 `#vmp-<id>` 作用域之外，`def.css` 够不到它们；`opts.class` / `opts.style` 直接作用在整个遮罩层上（`modal` 想改主体框宽度和内边距，作用在返回的 `handle.box` 上）。

**② `def.css` 按 `.vpu-*` 类名覆写**

挂进 `root` 的组件（button/input/card/tabs/progress 等全部）受 `def.css` 管辖——它自动限定在 `#vmp-<id>`，直接按类名覆写即可，不外泄也不被外部污染：

```js
css: `
  .vpu-card { background: rgba(77,163,255,.08); border-color: rgba(77,163,255,.25); }
  .vpu-tab { font-size: 13px; }
`
```

**③ CSS 变量**

面板可用的 CSS 变量在插件里同样可读：`var(--svp-primary, #4da3ff)` 是当前主题主色。自己的样式跟随主题就写变量，别硬编码色值。

- `code` 支持 `async code(ctx) { ... }`：清理函数在 Promise 落定后登记（若切页早于落定，清理函数不会被执行，异步初始化请尽量放同步段）。

## 8. `ctx.project` 作品接口

由 bridge 背书的受控窄面（插件拿不到 vm/bridge 本体）。导出走官方 VM API（`vm.saveProjectSb3` / `vm.toJSON`），缺失时自动 polyfill；捕获由桥接层包装 `vm.loadProject` 实现（非枚举 + toString 拟真伪装，站点探测不到包装痕迹）。捕获为纯内存环形缓冲（最多 8 条，关闭自动捕获即清空），无持久化。

```js
code(ctx) {
  const sprites = ctx.project.listSprites();          // [{ id, name, costumeCount, soundCount }]
  ctx.project.exportSb3().then((blob) => saveAs(blob, 'project.sb3'));
  ctx.project.exportSprite(sprites[0].id);            // → Promise<Blob> (.sprite3)
  ctx.project.exportSpritesZip();                     // → Promise<Blob> (全部角色打包 zip)
  ctx.project.setCapture(true);                       // 自动捕获开关（关=清空）
  const list = ctx.project.listCaptured();            // [{ id, time, size, name }]
  const blob = ctx.project.getCapturedBlob(list[0].id); // → Promise<Blob | null>
  const un = ctx.project.onCaptured((e) => console(e)); // 新捕获订阅，返回取消函数
  ctx.project.clearCaptured();
}
```

| 方法 | 说明 |
|---|---|
| `exportSb3()` | 当前作品 → `Promise<Blob>`（.sb3；原生 `saveProjectSb3` 优先） |
| `exportSprite(targetId)` | 单个角色 → `Promise<Blob>`（.sprite3：sprite.json + 资产） |
| `exportSpritesZip()` | 全部角色打包 → `Promise<Blob>`（每角色一个 .sprite3 的 zip） |
| `listSprites()` | 角色清单（id/名称/造型数/声音数，不触资产数据） |
| `setCapture(enabled)` | 自动捕获开关；关闭即清空已捕获条目 |
| `listCaptured()` | 捕获清单（元信息 id/time/size/name） |
| `getCapturedBlob(id)` | 取某条捕获的 Blob（过期 id → `null`） |
| `clearCaptured()` | 清空捕获列表 |
| `onCaptured(cb)` | 订阅新捕获，返回取消订阅函数（补丁订阅随生命周期自动退订） |

## 9. 调用 CCW 官方 API

CCW 官方前后端接口（与社区 SDK `@ccw-api/api` 同源）覆盖六大服务。插件 `code` 运行在页面上下文，**可直接用 `fetch` 调用**——VaIMod 不封装、不代理这些请求：何时调用、是否消耗账号权益（金币、签到、打赏等），由插件作者自行决定并向用户说明。

### 9.1 运行环境与请求约定

- 解析期只把 `VaIMod` 交给插件（详见第 11 节的安全边界说明），但 `code` 运行期是完整页面环境，`fetch` / `URL` / `JSON` 全部可用。
- 响应统一外壳 `{ code, msg, body }`：**成功判断看 `code`，数据取 `body`**。
- 带登录态的请求务必 `credentials: 'include'`（靠浏览器 cookie 会话鉴权，与站点本身一致）。
- 分页约定：GET 走 query（`page` / `perPage` / `sortField` / `sortType`），返回 `data` + `totalNum` + `totalPages`；POST 走 JSON body。

```js
async function api(path, opts = {}) {
  const res = await fetch(path, {
    credentials: 'include',
    headers: opts.body ? { 'Content-Type': 'application/json' } : undefined,
    ...opts,
  });
  const json = await res.json();
  if (json.code !== 0) throw new Error(json.msg || '请求失败');
  return json.body;
}
```

### 9.3 完整示例：签到面板

```js
VaIMod.plugin({
  type: 'ext',
  id: 'checkin-helper',
  name: '签到助手',
  css: '.vpu-progress { margin-top: 4px; }',
  async code(ctx) {
    const ui = ctx.ui;
    const state = ui.badge('查询中…');
    const bar = ui.progress({ value: 0 });
    const log = ui.tip('准备就绪', 'info');
    const go = ui.button({
      text: '今日签到',
      kind: 'primary',
      onclick: async () => {
        const ok = await ui.confirm({ title: '签到', message: '确定今日打卡？' });
        if (!ok) return;
        go.classList.add('busy');
        try {
          const res = await fetch('https://community-web.ccw.site/check_in_record/insert', {
            method: 'POST',
            credentials: 'include',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ scene: 'HOMEPAGE' }),
          });
          const json = await res.json();
          bar.update(100);
          state.textContent = json.code === 0 ? '已签到' : '失败';
          log.textContent = json.msg || '';
          ctx.toast(json.code === 0 ? '签到成功' : '签到失败', json.code === 0 ? 'ok' : 'err');
        } catch (e) {
          ctx.toast('网络错误：' + e.message, 'err');
        } finally {
          go.classList.remove('busy');
        }
      },
    });
    ctx.root.append(
      ui.card({ title: '每日签到', children: [ui.row(state, go), bar, log] }),
    );
    return () => {}; // fetch 无需清理
  },
});
```

> ⚠️ 写操作（签到 / 打赏 / 提交分数 / 改资料）属于消耗账号权益的行为：插件里做这类事之前用 `ui.confirm` 向用户二次确认，这是生态惯例，也避免用户误触。

## 10. 生命周期

**扩展（ext）：**

```
上传安装 ──► 解析校验（沙箱执行一次，只收定义不跑 code）
   │
启用 ──► 标签栏出现以 name 命名的 Tab
   │
切到该 Tab ──► 注入 html ──► 执行 code(ctx) ──► 返回值若为函数则记为清理函数
   │            └─ 若声明了 async：先等 vm 就绪（waitVm）──► 跑预加载钩子（load）
   │               ──► 再执行 code。等待期间显示「插件加载中…」；
   │               超时 / load 抛错 = 加载失败，**不执行 code**，页内显示原因
   │
点面板「刷新」（停在本页）──► 执行 refresh(ctx)（未定义则只重播动画）
   │
离开 Tab / 改设置 / 升级插件 ──► 先调上次的清理函数 ──► 重注入 html ──► 重跑 code
```

**常驻扩展（`async.lazy === false`）**：不切到它的 Tab 也会执行 `code`，实例是 headless 的
（不注入 html、不渲染 DOM，`ctx.root` 为游离节点）。当前正被打开的插件页不会重复实例化。

**补丁（patch）：**

```
上传安装 ──► 确认来源 ──► 解析校验
   │
面板挂载 ──► 执行 code(ctx) ──► 注册管道钩子 ──► 钩子即时生效
   │
面板挂载期间 安装/启用补丁 ──► 立即运行；禁用/卸载/升级 ──► 清理函数 + 钩子注销
```

**计时器、事件监听、`onVariables` 订阅必须在 `return` 的清理函数里释放**，否则切页/重跑都会泄漏一份（补丁的 `onVariables` 例外：随生命周期自动退订）。

## 11. 解析与安全边界

- 上传后以 `new Function('VaIMod', 'ValMod', src)` 执行一次收集定义（第二个参数是更名前的旧全局名，两者指向同一收集器——更名前写的插件文件不改也能继续安装）。**要如实理解这条边界**：函数体作用域就是全局作用域，解析期代码技术上仍能触达 `window` / `document` / `localStorage` / `fetch`。所以插件代码的信任级别**等同于页面脚本**——「只有 `VaIMod` 一个全局」指的是 VaIMod 只把 `VaIMod` 交给插件，不是技术上不可达。请只安装你信任来源的插件。
- 存储态有完整性指纹（`bodySig`）：落盘条目被外部脚本改写或写坏，启动时会被拒绝加载并在设置页给出告警（重新上传即可修复）。这只防「别人往 `localStorage` 塞插件」，不能防插件作者本人写坏事。
- 文件上限 512 KB；必须是合法 JS（编辑器有语法高亮）。
- 运行期经 `ctx` 拿受控能力：`ctx` **不提供** vm / bridge / VaIMod 内部对象，写变量只能走 `ctx.write`（经面板写回漏斗 + 补丁拦截 + 锁同步）。可自由操作自己 `root` 内的 DOM，跨插件/跨站点互不影响。
- **`code` / `refresh` / `async.load` 各自被单独编译执行**（分别 `new Function('ctx', …)`），彼此**不共享作用域**：插件文件顶层的变量、以及 `code` 内的局部变量，`refresh` 都取不到。跨这两段传状态用 `ctx.root`（同一插件页内 `root` 元素复用）。
- `html` 按**声明式结构**处理：渲染前会剥掉脚本类元素（`script` / `iframe` / `object` / `embed` / `link` / `meta` / `base` / `form`）、所有 `on*` 事件属性和 `javascript:` / `data:text/html` 形式的 URL。交互一律写进 `code`（`addEventListener` 或 `ctx.ui`），不要在 html 里写内联事件。
- 安装去重用源码指纹（FNV-1a 双通道 64 位），改一个字符即为不同版本。

## 12. 常见坑

1. `setInterval` / `addEventListener` / `ctx.onVariables` 不清理 → 切一次页泄漏一次（补丁的 `onVariables` 除外）。
2. 解析期虽然能碰到 `window` / `document`，但**别用**：文件顶层只调 `VaIMod.plugin({...})`，把副作用留给运行期 `code`。文件顶层抛异常会导致安装失败。
3. `code` 写成字符串形态时，内容是**函数体**（如 `'ctx.toast("hi")'`），不是完整 `function` 声明。
4. `store` 只存 JSON 可序列化数据（对象/数组/字符串/数字/布尔）。
5. 想升级插件就保持 `id` 不变；`id` 一变就是全新插件。
6. `settingsCss` 是整页生效的，选择器务必写具体（如 `.svp-plug-card .xxx`）。
7. 补丁忘了声明 `type: 'patch'` → 被当成扩展，没有 `ctx.patch`，钩子注册不上。
8. html 里写 `<form>` / 内联 `onclick` → 会被净化剥离，交互请走 `code`。
9. 补丁的 `html` / `css` 不会渲染（无标签页），别把 UI 逻辑写进补丁。
9. `ui.modal` 仅扩展插件可用（补丁 headless 直接抛错）；弹窗别叠多层——confirm 与 modal 同时开着时按 Esc 会一起关掉。
10. 调 CCW 官方 API 记得 `credentials: 'include'`，成功判断看响应壳的 `code`、数据取 `body`；写操作前先 `ui.confirm` 二次确认。
11. `refresh(ctx)` 里不要重新订阅 `onVariables` / `onSettings`——它与 `code` 共享同一个 ctx，重复订阅会泄漏且回调翻倍。
12. **`code` 与 `refresh` 是两个各自独立编译的函数体，不共享闭包**：文件顶层的 `let` / `const`、以及 `code` 内部的局部变量，在 `refresh` 里**一律不可见**（引用会抛 `ReferenceError`）。两者要共享状态，把它挂在 `ctx.root` 上（如 `ctx.root.__rerender = render`），`refresh` 里 `ctx.root.__rerender` 取用、清理函数里 `delete ctx.root.__rerender`；`ctx.store` 只能存 JSON 可序列化数据，放不了函数。参考 `plugin-sb3-toolbox.js` 的 `__rerender` 写法。
13. 插件 `code` 里抛出的异常会被 `runPluginCode` 捕获并转成一条 **toast**（不是常驻提示）：面板看起来「挂载了但一片空白」时，先看有没有一闪而过的红色 toast。
