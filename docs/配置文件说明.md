# VaIMod 配置文件说明

VaIMod 的配置文件是一个 JSON 文件，面板头部「导出配置」生成，文件名形如 `VaIMod-bundle-<作品id>-<时间戳>.json`。它是一份**完整备份**：变量、显示别名、云数据镜像、飞书机器人、快照、回收站、面板设置、已安装插件（含源码）、**插件设置值**、**插件启停态**、**改动记录**全部在内，换设备导入即可一键还原。

从面板头部的「导入配置」按钮选择 JSON 文件即可应用。旧版格式也能识别：

| 导入的文件 | 处理方式 |
|---|---|
| `vaimod-bundle-v2`（当前） | 全量应用 |
| `vaimod-bundle-v1` | 全量应用（`pluginSettings` / `pluginState` / `modified` 三项缺省 = 不动设备现状） |
| 只含 `{ project, variables }` 的纯变量 JSON | 自动升级，只应用变量，其余字段保持设备现状 |

## 一、顶层结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `app` | string | 固定 `"VaIMod"`，识别标记 |
| `version` | string | 格式版本，当前 `vaimod-bundle-v2` |
| `exportedAt` | string | 导出时间（ISO 8601） |
| `project` | string | 导出时的作品 id（仅记录用） |
| `variables` | 数组 | 变量条目列表，见下文（支持 `"*"` 通配） |
| `displayNames` | 对象 | 手动显示别名，键是 **`v:<角色 id>:<变量 id>`**（不是变量名！按名写请用下面的 `aliasConfig`） |
| `aliasConfig` | 对象 | **本地重命名规则表**（v2 新增可选字段，按真实变量名匹配，见第七节）。缺省 = 不动设备上现有配置 |
| `cloudProject` | 对象 | 作品云数据镜像 |
| `cloudUser` | 对象 | 用户云数据镜像 |
| `robots` | 数组 | 飞书机器人（token 等） |
| `markers` | 数组 | 快照标记（还原点） |
| `trash` | 数组 | 回收站条目 |
| `settings` | 对象 | 面板设置（异步加载 / 主色调 / 标签页顺序与显隐等） |
| `plugins` | 字符串数组 | 已安装插件的完整 JS 源码 |
| `pluginState` | 数组 | 已安装插件的**启停态与安装信息**（v2 新增，见第六节） |
| `pluginSettings` | 对象 | **插件设置页里各项的值**，按插件 id 分组（v2 新增，见第六节） |
| `modified` | 数组 | **改动记录**：哪些变量被改过/被锁，以及原始值（v2 新增，见第六节） |

## 二、变量条目字段

```json
{
  "name": "分数",
  "targetName": "角色1",
  "kind": "variable",
  "value": 0,
  "isLocked": true,
  "lockInterval": 1000
}
```

| 字段 | 说明 |
|---|---|
| `name` | 变量名；**写成 `"*"` 即进入自动检测通配模式**（见第三节） |
| `targetName` | 限定目标（角色/舞台）名；空串表示不限目标 |
| `kind` | `"variable"`（变量）或 `"list"`（列表） |
| `value` | 默认值；变量为字符串/数字，列表为数组 |
| `isLocked` | 是否锁定（锁定后 VaIMod 按 `lockInterval` 毫秒周期把值写回） |
| `lockInterval` | 锁定写入间隔（毫秒），仅 `isLocked: true` 时有意义 |

导入时逐条校验，格式不对的条目直接丢弃，不影响其余条目。

## 三、变量 `"*"` 自动检测模式（通配）

### 解决什么问题

给变量逐个写配置太死板：换个作品、变量名不一样就全部失配。把条目的 `name` 写成 `"*"`，表示**不绑定具体变量名**——导入时按当前项目**动态检测**：凡是项目里存在的变量/列表，全部自动套用这条配置的默认值与锁定策略。

### 最小示例

```json
{
  "app": "VaIMod",
  "version": "vaimod-bundle-v2",
  "variables": [
    { "name": "*", "targetName": "*", "kind": "variable", "value": "0", "isLocked": true, "lockInterval": 1000 }
  ]
}
```

这份配置导入后的效果：当前项目里**所有普通变量**都被设为默认值 `"0"` 并以 1 秒间隔锁定。以后作品里**新增的变量**同样自动纳入，无需改配置、无需重新导入。

### 规则细节

1. **具名优先**：同一份配置里如果同时有具名条目和通配条目，先按具名精确匹配；通配条目只补齐**没有被具名命中**的变量。
2. **按 kind 匹配**：通配条目只套同类。普通变量需要 `kind: "variable"`，列表需要**单独一条** `kind: "list"` 的通配条目（value 为数组）。没有列表条目时列表不会被通配覆盖。
3. **`targetName` 语义**：
   - `"*"` 或空串 → 不限目标，所有角色/舞台下的变量都套用；
   - 写具体目标名（如 `"角色1"`）→ 只套该目标下的变量。
4. **多目标同名变量**：具名条目不写 `targetName` 时，同名变量的每个实例都会命中。
5. **匹配不到的具名条目**不会报错，导入完成后的摘要里会体现为未生效。

### 混合示例（推荐写法）

```json
{
  "app": "VaIMod",
  "version": "vaimod-bundle-v2",
  "variables": [
    { "name": "分数", "targetName": "", "kind": "variable", "value": 0, "isLocked": true, "lockInterval": 500 },
    { "name": "排行榜", "targetName": "", "kind": "list", "value": ["a", "b", "c"], "isLocked": false },
    { "name": "*", "targetName": "*", "kind": "variable", "value": "0", "isLocked": false }
  ]
}
```

效果：`分数` 精确锁定为 0（500ms 周期）；`排行榜` 精确恢复为三个元素；**其余所有变量**默认值 `"0"`、不锁定。

### 手写要点

- 通配条目的 `value` 是「模板值」——所有被它覆盖的变量都会被写成同一个值；只想统一锁定策略、不想改值的话，`isLocked` 按需写，`value` 保持一个无伤大雅的值即可（注意导入会把模板值写进去，这是预期行为）。
- 文件里只需要 `app` + `variables` 两个字段也能导入（`app: "VaIMod"` 是识别关键），其余字段缺省时保持设备现状。

## 四、插件部分

- `plugins` 是源码字符串数组。导入时自动逐条解析安装：代码完全一致的跳过，同 id 新版本的自动升级，单条失败不影响其余。
- 设置页插件管理的「导出全部」会生成 `VaIMod-plugins-<时间戳>.json`——一个**只含插件**的配置包（`variables` 等全为空）。用「导入配置」选择它只会安装插件，**不会**动设备上已有的变量/别名/快照/设置。
- 单个插件的「导出」按钮则产出 `.plugin.js` 源文件，可在插件管理页重新上传，也可分享给他人直接装。

## 五、导入会覆盖什么

完整配置包导入时，以下数据**全量覆盖**（导入前有确认弹窗，摘要里能看到包里各字段的数量）：

- 变量（写入 vm 实际值 + 锁定策略）、显示别名、快照、回收站、飞书机器人、面板设置、插件列表、
  **插件设置值**、**插件启停态**。

只想分享/迁移**部分**数据时，手写 JSON 删掉不需要的顶层字段即可（字段留空数组/空对象 = 不覆盖）。

## 六、v2 新增的三块内容

### 6.1 `pluginState` —— 插件启停态与安装信息

```json
{
  "id": "my-tool",
  "name": "我的工具",
  "version": "1.0.0",
  "type": "ext",
  "enabled": true,
  "installedAt": 1758000000000,
  "sig": "3f1a…"
}
```

`plugins` 只带源码，装回来默认是启用的；这一块补上**用户当时的启停态**——导入后
「我本来禁用了它」这件事不会被悄悄重置成启用。`sig` 是源码指纹，用来跨设备核对
「包里这份插件和你本机那份是不是同一个版本」。

### 6.2 `pluginSettings` —— 插件的设置值

```json
{
  "my-tool": { "live": true, "cloud": "local", "min": 2 }
}
```

按**插件 id** 分组，键名就是插件 `settings` 里定义的 `key`。插件作者新增/改名 `key`
也不会丢数据：导出会连「已保存但当前定义里没有的键」一起带走，往返不丢。

### 6.3 `modified` —— 改动记录（哪些变量被改过）

```json
{
  "name": "分数",
  "targetName": "角色1",
  "kind": "variable",
  "value": 999,
  "origin": "changed",
  "original": 0,
  "lockInterval": 0
}
```

只收录**偏离原始值**（`origin: "changed"`）或**处于锁定态**（`origin: "lock"`）的变量，
`original` 是导入/首次连接时读到的原始值。这份记录有两个用途：

1. **一眼看出这次都动了什么**（导入摘要里的「改过 / 锁定」计数就来自它）；
2. 换设备时能看见「这个值是改过的」而不是丢进一份无差别的变量表里。

> 注意：真正把值写回 vm 的是 `variables` 数组；`modified` 是**审计信息**，用来解释
> 「为什么会有这些值」。两者通常会同时存在。

## 七、常见问题

- **导入后变量值不对**：检查 `kind` 是否写对（列表必须 `kind: "list"`，value 是数组）。
- **通配没覆盖到某个变量**：是否已被具名条目命中（具名优先）；或该变量是列表但没有 `kind: "list"` 的通配条目。
- **只想备份插件**：用设置页「导出全部」，别用完整配置导出（会把变量/快照等一并带走）。
- **导入后插件设置没恢复**：先在设置页确认插件本体已装好（`plugins` 里的源码会逐条装）；`pluginSettings` 里的键即使当前插件定义里没有也会被原样保存，所以「没生效」通常是插件本身没读到该键，而不是配置丢了。
- **导入后插件被禁用了**：这是 `pluginState` 在忠实还原导出时的启停态；在设置页插件管理里重新启用即可。

## 八、本地重命名配置（`aliasConfig` / 独立 JSON）

### 它是什么

一份**只改显示**的重命名规则表：把「真实变量名（常是混淆名）→ 中文显示名」写下来，
变量页里就按中文名显示。**它不新建变量、不改作品里的变量名、不写任何值** ——
对项目、云端、联机同步都是零影响，也不会被「改名/新建检测」盯上。

和 `displayNames` 的区别（两张表按优先级叠加）：

| | `displayNames` | `aliasConfig.rules` |
|---|---|---|
| 键 | **变量 id**（`v:<角色id>:<变量id>`） | **真实变量名**（支持 `*` 通配） |
| 来源 | 变量页点「重命名」手动改的那一条 | 手写 / 导入的 JSON 配置 |
| 特点 | 精确锁定某一个变量 | 人可读、可手改、可分享；换作品仍按名匹配 |
| 优先级 | **高**（先看它） | 低（它没有才看规则表） |

### 独立 JSON 格式

设置页 →「本地重命名」→「导入 JSON」/「导出 JSON」。推荐格式：

```json
{
  "version": 1,
  "name": "cave.io 中文变量名",
  "source": "plugin-cave-helper",
  "enabled": true,
  "rules": [
    {
      "match": "n95~]F1M+?",
      "label": "实体血量表",
      "scope": "Stage",
      "note": "证据：写这里的原因，只给人看"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `match` | 是 | 真实变量名；支持 `*` 通配（`n95*`、`*health*`）。简单前后缀通配，**不解析正则**（配置可手写，避免 ReDoS） |
| `label` | 是 | 本地显示名 |
| `scope` | 否 | 限定角色。`Stage` / `player` / 具体角色名 / `any`（省略即不限） |
| `note` | 否 | 备注，不参与匹配 |

> **`scope: "Stage"` 会自动兼容各语言的舞台名**（`舞台` / `ステージ` / `Scene` …）。
> 面板拿到的 `targetName` 是 Scratch 的本地化名，直接比较会永远对不上 —— 归一化在
> `core/alias-config.ts` 的 `canonTarget()` 里做。

### 四种可导入的格式

导入器会依次尝试，认不出就整份拒绝（不会写半份进去）：

1. **原生**：`{ version, name, rules: [{ match, label, scope? }] }`
2. **`cave-vars.json` 直接导入**：`{ variables: [{ name, label, scope, … }] }`
   （仓库 `docs/cave-vars.json` 就是这个形态，选它导入即可，无需转换）
3. **配置包片段**：`{ displayNames: { "真实名": "显示名" } }`
4. **扁平表**：`{ "真实名": "显示名" }`

### 边界与上限

- 规则数上限 5000 条；单条 `match` / `label` 上限 256 字符，`note` 上限 512 字符；
  文件上限 2 MB。超限**整份拒绝**（不截断），避免出现「半份配置生效」这种难排查的中间态。
- 非字符串的键/值一律丢弃；`__proto__` / `constructor` / `prototype` 作为键会被拒绝，
  不会被写进对象（原型污染防护）。
- 「清空本地记忆」会**一并清掉**这份规则表（和 `displayNames` 一样走模块 API 清，
  只删 localStorage 会因为模块缓存而清不干净）。
- 导入的**显示名一律当纯文本**渲染，永不进 `innerHTML`（别名来自任意 JSON）。

### 从 cave 插件一键生成

`cave.io 助手` 插件的变量对照表里有「**变量名本地改中文**」按钮：
它把插件内置的 37 条逆向字典直接转成上面的 `rules` 导入，
变量页立刻按中文名显示 —— 而作品里的变量名、个数、id、值全部原样不动。
旁边「恢复原名」按钮清空规则表。

## 九、网络防火墙（**已移出本体，不再是配置包字段**）

> ⚠️ 版本变更：网络防火墙已从「本体内置能力」改成一份**可分发的独立插件**
> （`docs/plugin-net-firewall.js`）。
> - **不导入插件，就完全没有这个功能**：没有标签页、没有设置项、没有任何网络钩子；
> - 因此配置包里**不再有 `firewallRules` 字段**（v2 及更早的包也一样，字段不存在就是不存在）；
> - 防火墙的**模式与域名规则存在插件自己的私有存储里**（`vaimod_plug_net-firewall_*`），
>   不随配置包导出/导入。要搬走到别的设备，用插件页里的「导出规则 / 导入规则」按钮。

### 它是什么（导入插件后）

一份**域名黑白名单** + 一个模式开关（关闭 / 监视 / 拦截），决定页面往站外的请求怎么处理。
默认模式是**关闭**，关闭态下不安装任何网络钩子（零开销、零行为变化）。

安全底线：打开后**默认建议用「监视」——只记录、全部放行，不改变站点任何行为**。
只有用户显式把域名写进 `block`（且模式为「拦截」）时，命中该域名的请求才会被拒绝。

导出的规则文件形如：

```json
{
  "name": "VaIMod 防火墙规则",
  "version": 1,
  "block": ["suspicious.example", "*.tracker.example"],
  "allow": ["cdn.example.com"]
}
```

| 字段 | 说明 |
|---|---|
| `block` | 黑名单：**拦截模式**下命中即拒绝 |
| `allow` | 白名单：优先于黑名单，命中即放行（记录为 `allow`，不拦） |

也接受**纯数组**导入（视为整份黑名单）。

### 域名写法

| 写法 | 匹配 |
|---|---|
| `example.com` | `example.com` **及全部子域**（`a.example.com`） |
| `*.example.com` | 仅子域，不含 `example.com` 本身 |

不解析正则（防 ReDoS），不支持端口与路径。同一域名不能同时出现在黑白两份里 ——
插件页里加进一边会自动从另一边移除，避免规则互相矛盾。

### 不进日志的请求

- **同源请求**（与当前页面同协议+域名+端口）；
- **站点同族域名**（当前页是 `ccw.site` 时，`m.ccw.site` / `community-web-cloud-database.ccw.site` 等全部子域）；
- VaIMod 自己发起的请求（云数据直写等，本体用 `ctx.net.isInternalXhr` 标记后插件直接透传）。

所以日志天然是「**站外**」视图，不会被站点自身的几十个请求淹掉。

### 日志里的四种判定

| 判定 | 含义 | 拦截模式下 |
|---|---|---|
| `third` | 普通第三方出网 | 放行 |
| `block` | 命中用户黑名单 | **拒绝** |
| `exfil` | **疑似把变量/存档数据外发**（POST 体积 ≥ 8 KB，或载荷/参数命中变量数据特征） | 默认放行；开启「拦截数据外传」后拒绝 |
| `allow` | 命中用户白名单 | 放行 |

### 上限与安全边界

- 黑/白名单各上限 500 条；主机名上限 253 字符；日志上限 300 个不同主机（环形缓冲，不会无限增长）。
- 非法域名（含空格、超长、`..`）**整体拒绝**，不会写进规则表。
- 模式为「关闭」时**不安装任何网络钩子**（零开销）；「监视」与「拦截」共用同一套钩子，
  切换只改判定结果，不会破坏其它模块叠加的包装层。
- 覆盖的通道：`fetch`、`XMLHttpRequest`（open + send）、`navigator.sendBeacon`、`WebSocket.send`（只观察）。
  **不碰** `img.src` / `script` / `link`（统计像素与 CDN 会大量误伤），也不替换 `WebSocket` 构造器
  （替换会改变 `instanceof` 与 toString 特征）。

### 和其他模块的关系

- 判定期任何异常都**放行** —— 防火墙绝不能成为站点的故障点。
- 飞书拦截（`feishuIntercept`）是本体能力、防火墙是插件，两层独立判定：先过防火墙，再过飞书拦截，互不影响。
- 插件里钩子的安装/卸载与「**切换标签页不清空日志**」的细节，见《插件开发文档》第 8.6 节。
