# VaIMod 配置文件说明

VaIMod 的配置文件是一个 JSON 文件，面板头部「导出配置」生成，文件名形如 `VaIMod-bundle-<作品id>-<时间戳>.json`。它是一份**完整备份**：变量、显示别名、云数据镜像、飞书机器人、快照、回收站、面板设置、已安装插件（含源码）、**插件设置值**、**插件启停态**、**改动记录**全部在内，换设备导入即可一键还原。

从面板头部的「导入配置」按钮选择 JSON 文件即可应用。旧版格式也能识别：

| 导入的文件 | 处理方式 |
|---|---|
| `vaimod-bundle-v2`（当前） | 全量应用 |
| `vaimod-bundle-v1` | 全量应用（`pluginSettings` / `pluginState` / `modified` 三项缺省 = 不动设备现状） |
| 只含 `{ project, variables }` 的纯变量 JSON | 自动升级，只应用变量，其余字段保持设备现状 |

## 一、顶层结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `app` | string | 固定 `"VaIMod"`，识别标记 |
| `version` | string | 格式版本，当前 `vaimod-bundle-v2` |
| `exportedAt` | string | 导出时间（ISO 8601） |
| `project` | string | 导出时的作品 id（仅记录用） |
| `variables` | 数组 | 变量条目列表，见下文（支持 `"*"` 通配） |
| `displayNames` | 对象 | 显示别名：`{ "真实变量名": "显示名" }` |
| `cloudProject` | 对象 | 作品云数据镜像 |
| `cloudUser` | 对象 | 用户云数据镜像 |
| `robots` | 数组 | 飞书机器人（token 等） |
| `markers` | 数组 | 快照标记（还原点） |
| `trash` | 数组 | 回收站条目 |
| `settings` | 对象 | 面板设置（异步加载 / 主色调 / 标签页顺序与显隐等） |
| `plugins` | 字符串数组 | 已安装插件的完整 JS 源码 |
| `pluginState` | 数组 | 已安装插件的**启停态与安装信息**（v2 新增，见第六节） |
| `pluginSettings` | 对象 | **插件设置页里各项的值**，按插件 id 分组（v2 新增，见第六节） |
| `modified` | 数组 | **改动记录**：哪些变量被改过/被锁，以及原始值（v2 新增，见第六节） |

## 二、变量条目字段

```json
{
  "name": "分数",
  "targetName": "角色1",
  "kind": "variable",
  "value": 0,
  "isLocked": true,
  "lockInterval": 1000
}
```

| 字段 | 说明 |
|---|---|
| `name` | 变量名；**写成 `"*"` 即进入自动检测通配模式**（见第三节） |
| `targetName` | 限定目标（角色/舞台）名；空串表示不限目标 |
| `kind` | `"variable"`（变量）或 `"list"`（列表） |
| `value` | 默认值；变量为字符串/数字，列表为数组 |
| `isLocked` | 是否锁定（锁定后 VaIMod 按 `lockInterval` 毫秒周期把值写回） |
| `lockInterval` | 锁定写入间隔（毫秒），仅 `isLocked: true` 时有意义 |

导入时逐条校验，格式不对的条目直接丢弃，不影响其余条目。

## 三、变量 `"*"` 自动检测模式（通配）

### 解决什么问题

给变量逐个写配置太死板：换个作品、变量名不一样就全部失配。把条目的 `name` 写成 `"*"`，表示**不绑定具体变量名**——导入时按当前项目**动态检测**：凡是项目里存在的变量/列表，全部自动套用这条配置的默认值与锁定策略。

### 最小示例

```json
{
  "app": "VaIMod",
  "version": "vaimod-bundle-v2",
  "variables": [
    { "name": "*", "targetName": "*", "kind": "variable", "value": "0", "isLocked": true, "lockInterval": 1000 }
  ]
}
```

这份配置导入后的效果：当前项目里**所有普通变量**都被设为默认值 `"0"` 并以 1 秒间隔锁定。以后作品里**新增的变量**同样自动纳入，无需改配置、无需重新导入。

### 规则细节

1. **具名优先**：同一份配置里如果同时有具名条目和通配条目，先按具名精确匹配；通配条目只补齐**没有被具名命中**的变量。
2. **按 kind 匹配**：通配条目只套同类。普通变量需要 `kind: "variable"`，列表需要**单独一条** `kind: "list"` 的通配条目（value 为数组）。没有列表条目时列表不会被通配覆盖。
3. **`targetName` 语义**：
   - `"*"` 或空串 → 不限目标，所有角色/舞台下的变量都套用；
   - 写具体目标名（如 `"角色1"`）→ 只套该目标下的变量。
4. **多目标同名变量**：具名条目不写 `targetName` 时，同名变量的每个实例都会命中。
5. **匹配不到的具名条目**不会报错，导入完成后的摘要里会体现为未生效。

### 混合示例（推荐写法）

```json
{
  "app": "VaIMod",
  "version": "vaimod-bundle-v2",
  "variables": [
    { "name": "分数", "targetName": "", "kind": "variable", "value": 0, "isLocked": true, "lockInterval": 500 },
    { "name": "排行榜", "targetName": "", "kind": "list", "value": ["a", "b", "c"], "isLocked": false },
    { "name": "*", "targetName": "*", "kind": "variable", "value": "0", "isLocked": false }
  ]
}
```

效果：`分数` 精确锁定为 0（500ms 周期）；`排行榜` 精确恢复为三个元素；**其余所有变量**默认值 `"0"`、不锁定。

### 手写要点

- 通配条目的 `value` 是「模板值」——所有被它覆盖的变量都会被写成同一个值；只想统一锁定策略、不想改值的话，`isLocked` 按需写，`value` 保持一个无伤大雅的值即可（注意导入会把模板值写进去，这是预期行为）。
- 文件里只需要 `app` + `variables` 两个字段也能导入（`app: "VaIMod"` 是识别关键），其余字段缺省时保持设备现状。

## 四、插件部分

- `plugins` 是源码字符串数组。导入时自动逐条解析安装：代码完全一致的跳过，同 id 新版本的自动升级，单条失败不影响其余。
- 设置页插件管理的「导出全部」会生成 `VaIMod-plugins-<时间戳>.json`——一个**只含插件**的配置包（`variables` 等全为空）。用「导入配置」选择它只会安装插件，**不会**动设备上已有的变量/别名/快照/设置。
- 单个插件的「导出」按钮则产出 `.plugin.js` 源文件，可在插件管理页重新上传，也可分享给他人直接装。

## 五、导入会覆盖什么

完整配置包导入时，以下数据**全量覆盖**（导入前有确认弹窗，摘要里能看到包里各字段的数量）：

- 变量（写入 vm 实际值 + 锁定策略）、显示别名、快照、回收站、飞书机器人、面板设置、插件列表、
  **插件设置值**、**插件启停态**。

只想分享/迁移**部分**数据时，手写 JSON 删掉不需要的顶层字段即可（字段留空数组/空对象 = 不覆盖）。

## 六、v2 新增的三块内容

### 6.1 `pluginState` —— 插件启停态与安装信息

```json
{
  "id": "my-tool",
  "name": "我的工具",
  "version": "1.0.0",
  "type": "ext",
  "enabled": true,
  "installedAt": 1758000000000,
  "sig": "3f1a…"
}
```

`plugins` 只带源码，装回来默认是启用的；这一块补上**用户当时的启停态**——导入后
「我本来禁用了它」这件事不会被悄悄重置成启用。`sig` 是源码指纹，用来跨设备核对
「包里这份插件和你本机那份是不是同一个版本」。

### 6.2 `pluginSettings` —— 插件的设置值

```json
{
  "my-tool": { "live": true, "cloud": "local", "min": 2 }
}
```

按**插件 id** 分组，键名就是插件 `settings` 里定义的 `key`。插件作者新增/改名 `key`
也不会丢数据：导出会连「已保存但当前定义里没有的键」一起带走，往返不丢。

### 6.3 `modified` —— 改动记录（哪些变量被改过）

```json
{
  "name": "分数",
  "targetName": "角色1",
  "kind": "variable",
  "value": 999,
  "origin": "changed",
  "original": 0,
  "lockInterval": 0
}
```

只收录**偏离原始值**（`origin: "changed"`）或**处于锁定态**（`origin: "lock"`）的变量，
`original` 是导入/首次连接时读到的原始值。这份记录有两个用途：

1. **一眼看出这次都动了什么**（导入摘要里的「改过 / 锁定」计数就来自它）；
2. 换设备时能看见「这个值是改过的」而不是丢进一份无差别的变量表里。

> 注意：真正把值写回 vm 的是 `variables` 数组；`modified` 是**审计信息**，用来解释
> 「为什么会有这些值」。两者通常会同时存在。

## 七、常见问题

- **导入后变量值不对**：检查 `kind` 是否写对（列表必须 `kind: "list"`，value 是数组）。
- **通配没覆盖到某个变量**：是否已被具名条目命中（具名优先）；或该变量是列表但没有 `kind: "list"` 的通配条目。
- **只想备份插件**：用设置页「导出全部」，别用完整配置导出（会把变量/快照等一并带走）。
- **导入后插件设置没恢复**：先在设置页确认插件本体已装好（`plugins` 里的源码会逐条装）；`pluginSettings` 里的键即使当前插件定义里没有也会被原样保存，所以「没生效」通常是插件本身没读到该键，而不是配置丢了。
- **导入后插件被禁用了**：这是 `pluginState` 在忠实还原导出时的启停态；在设置页插件管理里重新启用即可。
